# Demo video script (about 4 minutes)

Record your screen with a terminal on the left and the browser on the right (QuickTime → File → New Screen Recording).
**Never show `.env`** (it contains API keys). Close other tabs. Zoom the browser to ~110%.

The assignment's required storyline is: *crawler starts → discovers → extracts → identifies official source → verifies →
generates confidence → stores → displays → runs again → detects changes.* Each step below maps to it.

---

## Before you press record (2 minutes of setup)

```bash
cd assignment_edxo_again && source .venv/bin/activate
python -m scholarship_intel audit                 # confirm the minimums for the real database
python -m scholarship_intel demo-changes          # builds data/atlas_demo.db (labelled change/expiry demo)
```
Open two terminals:
* Terminal A (real data):  `python -m scholarship_intel serve --port 8010`  → http://127.0.0.1:8010
* Terminal B (demo copy):  `ATLAS_DB=data/atlas_demo.db python -m scholarship_intel serve --port 8011`  → http://127.0.0.1:8011

(Port 8000 is often used by another program on your Mac; 8010/8011 avoid the clash.)

---

## Scene 1 — The problem and the rule (0:00–0:30) · show `README.md` top / `docs/CONFIDENCE.md`
**Say:** "Atlas needs a repository of authentic scholarships for Indian students. The rule I built around is: *a scholarship
is only trusted if every important fact can be quoted from its official source, and the confidence score is computed
from evidence, never generated by an AI.* Aggregators and search results are only leads."

## Scene 2 — Crawler starts and discovers (0:30–1:30) · terminal
```bash
python -m scholarship_intel run --max-pages 40 --label "demo"
```
(If time is short, run it with `--no-search`, or show the already-finished run in the dashboard's *Crawl runs* tab.)
**Point at the log lines as they scroll:**
* `search[...]` and `provider-site[...]` → "discovery is search- and link-driven, not a list of scholarship URLs".
* `lead '…' -> UNRESOLVED (kept out of the repository)` → "aggregator names that cannot be traced to an official page are rejected".
* `+ [NEW] 'Reliance Foundation Undergraduate Scholarships' CORPORATE_CSR 96.5% VERIFIED …` → "extracted, source classified,
  confidence computed, record stored — one line".
* `⌫ retired … no indication the programme is open to Indian students` → "the system removes its own mistakes".

## Scene 3 — The dashboard (1:30–2:15) · browser, http://127.0.0.1:8010
1. Top tiles: **Total discovered · Verified · Review required · Active · Expired · Recently updated · Average confidence.**
   "Verified means ≥ 95% confidence — everything else is REVIEW REQUIRED, and I show that honestly."
2. Type a name in the search box; filter by *Source type* (Government / University / Corporate CSR / NGO-Trust / International).

## Scene 4 — Open one scholarship: authenticity and trace (2:15–3:15) · open a VERIFIED record (e.g. a Reliance scholarship)
1. **Official source ↗** — click it: the page is on the provider's own domain. "Source type, tier and reason are stored."
2. **Why this score?** — walk down the nine components (source authority, live presence, application URL, eligibility
   support, deadline support, benefit support, freshness, extractor agreement, traceability). "Each point is computed;
   hover/read the reason text."
3. Click **trace ↗** next to *Closing date* — the modal shows
   **Database → Official source → Evidence → Extracted value**, with the exact sentence highlighted in the page.
   "If the deadline came from an FAQ page of the same official site, the trace points to that page."
4. Scroll to a field showing **Not specified** (e.g. an age limit) → "If the source doesn't say it, I don't invent it."
5. Open **Unsupported claims rejected** → "anything a model claimed that wasn't in the source is thrown away and logged."

## Scene 5 — Runs again and detects change (3:15–4:00) · browser http://127.0.0.1:8011 (the DEMO database)
1. Point at the yellow banner: **DEMO DATABASE … SIMULATED**. "Real sites rarely change within minutes, so I replay the real
   pipeline against a copy of real pages with a few clearly labelled edits."
2. **Changes** tab: show **CHANGE DETECTED** rows → old value → new value, date detected, source URL, old/new evidence.
3. Open a record whose page was removed → status **NO_LONGER_VERIFIABLE**; open an expired one → **EXPIRED**.
4. **Say:** "The real database never receives simulated values. Running `python -m scholarship_intel run` again on real data
   re-verifies every known record first — unchanged pages are skipped, changed fields are logged, removed pages are flagged."

## Closing line
"Show us what your crawler found" → show **Leads & rejections** briefly (unresolved aggregator leads) and finish on the dashboard.

---

### Troubleshooting during recording
* Dashboard empty → you started it against the wrong DB. Real: default `data/atlas.db`; demo: `ATLAS_DB=data/atlas_demo.db`.
* A live crawl is slow or a model returns "high demand" → that's the free tier; the pipeline falls back and keeps going.
  For a tight recording, show the finished run instead of waiting.
* Port already in use → pick another with `--port`.
